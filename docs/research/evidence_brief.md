## 1. The project idea under review
Solo engineer, ~12 h/week, Apple Silicon Mac (no CUDA), rented GPUs. Fine-tune a 1-3B open model to extract financial facts (value, concept, period, unit) from SEC 10-K/10-Q tables and text, serve it (vLLM, quantized), and measure an accuracy/cost/latency frontier vs frontier APIs on a public benchmark (FinTagging). Load-bearing thesis: "prior XBRL-extraction work reports accuracy but not serving cost or latency." Project #1 (FilingQA, mid-Phase 1) already has an iXBRL fact extractor with character offsets.

## 2. Novelty: what already exists
- **FinLoRA** (arXiv 2505.19819, May 2025, Open-Finance-Lab): LoRA/QLoRA/DoRA/rsLoRA on Llama-3.1-8B over 19 datasets incl. FiNER-139 (10k train/7.4k test subset) and FNXL (247 test). FiNER acc: 8B LoRA 74.10 vs GPT-4o 72.29; FNXL: 23.57 vs GPT-4o 42.41. Reports FINE-TUNING cost ("$14.66 to $16.54" on 4xA5000 at $0.26/GPU-h) and Figure 3 "Average inference time" per task: DERIVED from vector PDF: Llama LoRA FiNER 1.57 s, FNXL 2.24 s, XBRL Analysis 4.58 s per prompt vs fine-tuned Gemini 2.0 FL API 0.31/0.33/1.40 s. Measurement = HF transformers + bitsandbytes 8-bit, un-merged PEFT, batch size 1 in shipped scripts, sequential; no vLLM, no throughput, no $/query, no p50/p95, no sub-8B, no FinTagging. Prompts bundle 4 tagging questions with a tag-option list (1.8k/7.1k tokens).
- **FLaME** (Findings ACL 2025): per-dataset zero-shot API $ incl. FNXL (Llama 3 8B $0.06, GPT-4o $0.96, DeepSeek R1 $11.21) on a 988-sentence FNXL subsample; FNXL F1 <= 0.057 for every model under its own set-overlap metric with a Llama-3.1-8B extraction pass; no latency. Not comparable to fine-tuned FNXL numbers.
- **FinTagging v5** (arXiv 2505.20650, May 2026, TheFinAI; arXiv-only, no venue): already evaluates Qwen3-0.6B/1.7B, Llama-3.2-3B zero-shot (FinNI F1 0.0038/0.0541/0.1460; FinCL acc 0.0414/0.0735/0.0415) and fine-tuned BERT-large/FinBERT/SECBERT (SECBERT best end-to-end micro-F1 0.1779). Frontier: DeepSeek-V3 FinNI P/R/F1 0.5886/0.8430/0.6932, FinCL 0.1889; GPT-4o 0.5397 / 0.1829. Only cost line: "approximately 500 GPU-hours and $1,500 in API usage". Zero latency/throughput.
- **FinAI Contest 2025 Task 2** (IEEE CSCloud 2025): fine-tuned <=8B models on FinNI (200 samples) / FinCL (500 samples); public 8-bit Llama-3.1-8B LoRA adapters for FinNI/FinCL (HF LbbbbbY/FinAI_Contest_FinGPT) with NO published scores, latency or cost. FinVerse Agent (4-bit 8B + 15 adapters) paywalled, abstract names only accuracy metrics.
- **FHS** (arXiv 2608.06614, Aug 2026, TheFinAI, Linhai Ma): best FinCL linker: Qwen3-32B zero-shot + BM25 K=200 + hypothesis search; Acc 0.255 / R@1 0.185 on a 2,509-fact FinTagging subset (191 contexts: 110 tables, 81 text). Reports LLM calls/fact and wall-clock in HOURS on the clinical CodiEsp split only (FHS full 5.31 h per 3,144 facts on one B200 = DERIVED ~6.1 s/fact serial); nothing on the financial split; no $. Names "model families and scales ... robustness-cost trade-off" as future work.
- **Kulkarni & Kulkarni** (arXiv 2603.22651, Mar 2026): $/doc ($0.148-0.430) and p50 latency (21-74 s) for 25-field extraction from 10,000 SEC 10-K/10-Q/8-K with XBRL-derived labels; GPT-4o/Claude 3.5/Gemini 1.5/Llama-3-70B/Mixtral via vLLM; multi-agent patterns; private data; no small/fine-tuned models.
- **XBRLTagRec** (arXiv 2603.25263, IJCNN 2026): FLAN-T5-Large LoRA + Sentence-T5-XXL retrieval + ChatGPT-3.5 rerank (up to 26 API calls/numeral) on FNXL; Hits@1 0.8618 / Macro-F1 0.5050; no cost or latency numbers. **FLAN-FinXC** (NAACL 2024): FLAN-T5-Large LoRA, FNXL Macro-F1 66.23 / Hits@1 89.98 on the full test set; only "56 minutes/epoch" and an opaque "inference time: 2 minutes/sample".
- **Generic "fine-tuned small model vs frontier API with $ and latency" is well established (2024-2026)**: distil labs (Qwen3 0.6B-8B on vLLM, p50/p95/p99, "$3 vs $6,241 per 1M requests", public repo), Manulife "Beyond Accuracy" (SmolVLM-500M/2.2B, Qwen2.5-VL-3B/7B fine-tuned vs GPT-5/Claude on bank checks; $/doc, p95; public code), Olava (contract extraction on SEC EDGAR, $0.018 vs $0.149-0.456/doc), Mastercard "How Small Can You Go?" (270M-8B LoRA, F1 vs throughput Pareto), "Sub-Billion, Super-Frontier" (360M-3B QLoRA RE vs GPT-5.4), clinical NER distillation ("101x cheaper, 12x faster"), LoRA Land, Cost-of-Pass, "AI Agents That Matter", and the **Inference Engineering Pareto Atlas** (arXiv 2609.17863, Sep 2026: 54 vLLM configs of Qwen2.5-7B on L4/A100/H100 with $/M-token, FP8/AWQ quality-latency trade-offs; RunPod July-2026 prices).
- **Nothing found** that fine-tunes/distills a 1-4B model on FinTagging (FinNI+FinCL) and reports per-filing $, p50/p95 latency or throughput vs frontier APIs; arXiv abstract search XBRL AND (latency|throughput|quantization|vLLM|inference cost) = 0 results; HF model search "fintagging" = empty. Post-June-2026 check: FHS, VeriFin, EnterpriseBench, Reclassified-to-Conform, NORA — none. One UNVERIFIED ResearchGate preprint "A Schema-Aware Large Language Model for XBRL Tagging and Cross-Statement Consistency Checking" (Peng et al., 2026-07-07) could not be read. lm2445 (= Linhai Ma, TheFinAI) FinTagging_1000* HF datasets feed FHS (zero-shot), not a fine-tuning project.
- NORA (arXiv 2605.24910, May 2026): 6.6M-sentence iXBRL multi-attribute corpus (concept, time relation, scale, sign), SEC-BERT encoder, unreleased; argues iXBRL labels are "inherently noisy" (CPA random-sample error <5%).
- HiFi-KPI (LREC 2026, CC BY 4.0): 1.65M paragraphs from 10-K/10-Q iXBRL with (value, collapsed-concept, period, unit); encoders >0.906 macro-F1 on classification; LLMs 0.440 F1 on structured extraction; no small fine-tunes, no cost.

## 3. FinTagging data facts
- HF (TheFinAI): 8 repos, every one a single `test` split. Canonical v5 sets = `FinNI-eval-v2` (28,787 rows: context_index, context, query, answer) and `FinCL-eval-v2` (261,457 rows: context, category, entity, entity_type, query, answer). `FinTagging_Original_v2` (46,496) is a duplicated/misaligned union (2x261,457 triples, ids not aligned) — do not use as instance set. v1 sets (6,599 / 52,572) match arXiv v1 and the GitHub README.
- FinNI-eval-v2 audit: 12,310 negative rows (no facts), 16,477 positive; 261,457 (Fact,Type) pairs; duplicate contexts: 25,765 unique of 28,787 (1,852 dup groups, 204 with differing answers). Official dedup policy undocumented.
- Labels = (value string, 5-way type, us-gaap concept QName). NO period, unit, scale, sign, decimals, CIK, accession, fiscal year. Tables are raw reconstructed HTML (`<table><tr><td>`); FinCL queries linearize the row with ` | `. Value normalization is prompt-side only: strip $, %, commas; don't expand "million".
- Construction: rule-based iXBRL parser (parse_xbrl_report.ipynb: ix:nonFraction -> value/concept/type; only `us-gaap:`; 5 types; dedup on (value, concept); text blocks >20 chars). 142 10-Ks filed 2023-02-13..2025-02-13, 142 companies, 11 sectors. Human audit: 1,949 instances (928 sentence + 1,021 table) by 2 analysts + adjudicator, 96% agreement, kappa 0.81; corrections merged back without flags -> ~99.25% of entities are unaudited auto-labels; auto-label error rate not reported (DERIVED from kappa: ~10-14% flagged on a deliberately hard subset).
- Filing identifiers: v1 lists 30 CIKs; v5 publishes none of the 142. Recoverable via EDGAR full-text search on exact context phrases: agent recovered 111/142 registrants with 890 queries (file `scratchpad/research/recovered_eval_manifest.json`); full recovery needs ~2-3k queries or the authors.
- The GitHub-only training set (10 filings, 1,116 sentences + 953 tables, 25,199 entities, 1,435 concepts) is NOT company-disjoint from eval: AT&T, USA Compression, Ares Commercial RE (prior FY filings) and Loews (parent of CNA, same FY) appear in eval; 78 training instances are verbatim eval contexts (30 with identical labels). The paper's BERT baselines were trained on it.
- Metrics: FinNI = set-based pair P/R/F1, match iff entity string AND type exactly match (Appendix E); set-vs-multiset, per-instance vs global aggregation, normalization, unparseable output handling are all unspecified. NO public FinNI scorer for LLM outputs. FinCL = exact concept match accuracy over top-200 retrieved candidates; scorer (evaluate_NEN.ipynb) substitutes candidates[0] on parse failure. Candidate lists live in PRIVATE HF datasets; embedding index (OpenAI text-embedding-3-small + Elasticsearch) is behind a Google sign-in (GitHub issue #1 unanswered since Jul 2025). Only a BM25 jsonl (17,388 concepts) ships. => FinCL as published is NOT reproducible; FinNI is reproducible only by implementing one's own scorer and re-running the frontier models (28,787 instances x ~1,101 avg input tokens = ~31.7M input + ~5.0M output tokens per model).
- Taxonomy: 17,388 = FASB 2024 us-gaap elements (the shipped xsd/BM25 index; FHS uses it); 17,688 = union of 2023+2024 element names (paper v3-v5 wording). Numeric-type concepts (monetary/percent/shares/perShare/integer) = 8,596. FinCL-eval-v2 gold uses 3,953 distinct concepts; 2 concepts (33 rows) are 2023-only.
- Licenses: `FinTagging_Original` MIT; other 7 HF repos no license field; GitHub repo no LICENSE file; paper CC BY 4.0; underlying SEC text public domain.
- Frontier retrieval ceiling: official SAC retrieval Acc@200 ~0.33 overall (sentences >0.65, tables <0.30); FHS oracle Recall@200 0.734.

## 5. Feasibility facts
- MLX/mlx-lm 0.32 (2026-10-01): LoRA/DoRA/full FT for Qwen3, Qwen2.5, Llama 3.2, Gemma 3, SmolLM3, Phi-4-mini; reports tokens/s and peak memory; QLoRA on 4-bit base; grad checkpointing. NO published 1-4B training throughput (7B anchors: ~250 tok/s M1 Max, ~475 tok/s M2 Ultra). Attention backward materializes LxL matrix until PR #4563 (merged 2026-09-29, not yet in a pip release) -> keep max_seq_length <= 2048-4096, batch 1-2, grad-ckpt. No PEFT import/export in mlx-lm (PR closed Aug 2026): a ~50-line converter is needed (transpose lora_a/lora_b, prefix keys, lora_alpha = scale*r, target_modules, layers_to_transform). MLX 4-bit checkpoints are not servable by vLLM nor convertible by llama.cpp; fuse --dequantize -> fp16 safetensors -> AWQ/GPTQ/FP8 via llm-compressor.
- Rented GPU anchors (observed 2026-10-01): RunPod L4 $0.44-0.49/h, A5000 $0.16-0.27, A100 80GB $1.19-1.59, H100 $1.99-3.49; Lambda A10 $1.29, A100 $1.99, H100 $3.29-4.29; Modal L4 $0.80, A10 $1.10, A100 $2.10-2.50, H100 $3.95; AWS g5.xlarge (A10G) $1.006, g6.xlarge (L4) $0.805; Vast L4/4090 ~$0.32 (aggregator). - Serving: vLLM LoRA supported for Qwen2/Qwen3/Llama/Gemma3/Phi3/SmolLM3 (max-lora-rank default 16); merge_and_unload removes adapter latency; quantization: AWQ/GPTQ/Marlin/INT8/bnb on Ampere+Ada; native FP8 W8A8 only on SM>=8.9 (L4/L40S/H100), A10G/A100 fall back to W8A16; structured outputs via xgrammar (choice/regex/json/EBNF; "near-zero overhead"); GENRE-style trie decoding is the canonical pattern for long canonical identifiers. ## 6. Training data scale evidence
- FinLoRA: 10k FiNER examples -> 8B LoRA 74% acc (base 21%); FLAN-FinXC: full FNXL (62.8k sentences) 10 epochs; LoRA Land: no correlation between gains and train-set size beyond a sufficient sample; fine-tuning scaling law: LoRA data exponent small (0.025-0.081), saturates early; LIMA/OpenAI: 50-1,000 examples teach format; FinTagging's own BERT set = 1,116 instances. FNXL pipeline Hits@10 ~92%; constrained decoding helps classification-style selection (DOMINO warns naive implementations hurt); XGrammar near-zero overhead; ICD-coding analog uses trie decoding over 15k codes with QLoRA 7B.
