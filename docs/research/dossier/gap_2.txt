### notes
RESOLUTION: The canonical v5 FinNI set is TheFinAI/FinNI-eval-v2 (28,787 rows, split 'test'); it reproduces paper v5 Table 3/4 exactly (12,310 negatives, 16,477 positives, 261,457 Fact/Type pairs = FinCL-eval-v2 rows). FinTagging_Original_v2 (46,496) is a duplicated/misaligned union (2 x 261,457 triples, 10,044 extra all-negative rows, ids not aligned) and should not be used as the instance set. The 6,151/62,668 figure is a filtered subset that exists only in arXiv v2's text and was never released. REPRODUCIBILITY: FinNI - prompt and gold are public, the metric formula is public (Appendix E), but no official scorer or per-sample outputs exist, so the project must (a) implement the set-based pair P/R/F1 itself and document its dedup/normalization choices, and (b) re-run GPT-4o and DeepSeek-V3 itself on FinNI-eval-v2 (~31.7M input + ~5.0M output tokens per model, from paper Table 4) for a like-for-like comparison; quoting 0.6932/0.5397 next to own numbers is not defensible because neither the scorer nor even the instance set behind those numbers is pinned down publicly. FinCL - not reproducible as published: candidate lists are in private HF datasets, the embedding index is behind a Google sign-in, retrieval needs Elasticsearch + OpenAI text-embedding-3-small, and the scorer silently credits candidates[0] on parse failure; the shipped BM25 jsonl permits only a text-mode rebuild. Recommendation: scope the cost/latency frontier to FinNI (where a clean, public, self-run comparison is possible), treat FinCL as optional with an own-retrieval caveat, and ask the authors (GitHub issue, with user approval) for the FinNI scorer, the two rerank datasets, and clarification of which instance set the v2-v5 numbers used. Novelty support: paper v5 has zero mentions of latency/throughput and only an aggregate '500 GPU-hours and $1,500' cost line; small models (0.6B-3B) appear only zero-shot. Scoop-risk flag: lm2445 (HF, July-Aug 2026) is fine-tuning 1.5B-8B models on a FinTagging v1 split, though without any visible cost/latency reporting. Tooling caveat: the WebSearch budget was already exhausted when this task started, so discovery relied on direct fetches, HF/GitHub/arXiv APIs, and authenticated gh code/repo search; Semantic Scholar was rate-limited.
