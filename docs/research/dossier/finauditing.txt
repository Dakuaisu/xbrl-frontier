### task_summary
VERIFIED (arXiv HTML v1, v2, v3 downloaded and grepped locally). Benchmark of LLMs on professional-grade financial AUDITING over real US-GAAP XBRL filings (instance doc + schema + linkbases + US-GAAP taxonomy chunks) — NOT text/table-to-XBRL tagging. Three zero-shot tasks: (1) FinSM, Financial Semantic Matching, 330 instances: IR-style — given a query describing a financial term, the XBRL filing and taxonomy, return the set of mismatched/erroneous US-GAAP tags (HR@k, Recall@k, Macro-F1@k, k=5/10/20). (2) FinRE, Financial Relationship Extraction, 440 instances: 3-way classification of the relation error type between two given concepts (Reversal / Inappropriateness / CombinationErr; Acc, Macro P/R/F1). (3) FinMR, Financial Mathematical Reasoning, 332 instances: extract the reported value for a concept and recompute the correct value from calculation-linkbase relations; output JSON {extracted_value, calculated_value}; Accuracy via LLM-as-judge plus SER/EER/CER error rates. Inputs are long: avg 33,849 tokens (FinSM), 33,681 (FinRE), 35,678 (FinMR), max 65,030 (cl100k_base); paper sets max input 81,920 tokens, 512 generation tokens. Ground truth derived deterministically from 4,545 XBRL US Data Quality Committee (DQC) error messages (372 companies, 2020-2024), filtered to the 9 most frequent DQC error types and 218 SEC EDGAR filings; GPT-4o-mini used only as a parser of DQC messages. XBRL concept linking is central (taxonomy-grounded concept alignment, calculation/presentation relations), but the task is error detection/verification on an already-tagged filing, not extraction of (value, concept, period, unit) tuples from raw 10-K text or tables.

### relevance_to_idea
FinAuditing is a sibling benchmark from the same group as FinTagging (The Fin AI / Xiao-Yang Liu / Jimin Huang) but is an XBRL AUDITING / error-detection benchmark over already-tagged filings (mismatched tags, relation-error classification, calculation re-verification), not text/table -> (value, concept, period, unit) extraction. It does not directly compete with a FinTagging-style extraction target but must be cited as the closest taxonomy-grounded XBRL work. Effect on the novelty claim: (a) SUPPORTS it — accuracy only, no per-model latency/throughput/serving cost, no fine-tuned or quantized small models, no cost-accuracy frontier; (b) WORD IT CAREFULLY — v1 did disclose an aggregate budget ("320 GPU hours ... around $200 in API costs"), so claim "no per-model serving cost or latency / no cost-accuracy frontier" rather than "no mention of cost"; (c) the authors themselves (Appendix E, v2/v3) flag compact instruction-tuned models and lightweight fine-tuned classifiers as the natural low-cost deployment path but leave it unmeasured — a citable motivation; (d) it DOES include Llama-3.2-3B, Fin-R1 7B and Llama-3.1-8B zero-shot baselines, so "nobody has benchmarked small models" is false in the strict sense — the defensible statement is "no fine-tuned/distilled small models and no cost/latency measurements on FinTagging/FinAuditing/FNXL/FiNER". Reuse: FinMR (extract reported value + recompute) and FinSM could be a secondary long-context (~34k-token) stress test for a 1-3B extractor, though inputs far exceed typical small-model context budgets; the StartKit pipeline-vllm.ipynb gives a ready vLLM harness. Citing works checked: AuditFlow (arXiv 2606.03031, same group; GPT-5.5 agents on a FinMR sample, 82.09%) — no cost/latency in abstract; VERA-8B (2608.28402) — 8B audit model, no XBRL/FinAuditing/cost; Finch (2512.13168, ACL 2026 Findings) — reports minutes-per-workflow for frontier agents on spreadsheets, not XBRL. Nothing found that benchmarks small/distilled models on FinAuditing with cost or latency. Contest: paper names it the official benchmark of SecureFinAI Contest 2026 (IEEE IDS 2026 special track; _Sub subsets "for ICAIF 2026" per README); the contest README and cloud-conf.net page contain no cost/latency/model-size criteria (2026 task pages not found on readthedocs).
