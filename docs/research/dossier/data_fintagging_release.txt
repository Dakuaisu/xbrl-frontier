### notes
BOTTOM LINE ON TRAINING SPLIT: every TheFinAI FinTagging dataset on Hugging Face (FinTagging_Original, _Original_v2, FinTagging_BIO, _BIO_v2, FinNI-eval, FinNI-eval-v2, FinCL-eval, FinCL-eval-v2) has a single 'test' split and no train/validation split. A training set DOES exist but only on GitHub (The-FinAI/FinTagging: annotation/TrainingSet_Annotation.json + BERT/data/train_data_all.bio), built from 10 extra 10-K filings (1,116 sentences + 953 tables, 25,199 entities, 1,435 concepts) for the BERT baselines; its schema is {text, numeric_entities:[{value,type,concept}]}. The only HF repo with a train split is the third-party lm2445/FinTagging_1000 (800/200, Jul 2026). LABELS: concept QName + 5-way item type + value string only — NO period, unit, decimals, scale, sign, or filing metadata (CIK/company/fiscal year/accession/URL) anywhere in HF or GitHub data; the paper's own parse_xbrl_report.ipynb discards those fields. TABLES are raw reconstructed HTML (<table><tr><td>) in FinNI/Original/BIO; FinCL queries linearize the row with ' | ' separators. LICENSES: FinTagging_Original = MIT; FinTagging-Untagged-Data = Apache-2.0; all other six TheFinAI repos have no license key; GitHub repo has no LICENSE file; paper is CC BY 4.0. SCORING: FinNI exact match on (entity string, type) pairs; FinCL exact concept match (accuracy) over top-200 retrieved candidates; end-to-end triplet P/R/F1; normalization is prompt-side only (strip $, %, commas; don't expand 'million'). COST/LATENCY: the paper states only an aggregate '500 GPU-hours and $1,500 in API usage' (v5) and reports no latency, throughput, or per-sample cost; v1 ran open models via TogetherAI API. Small models (Qwen3-0.6B/1.7B, Llama-3.2-3B) are evaluated zero-shot only and score ~0.001-0.01 end-to-end F1 — consistent with the project's novelty claim that no fine-tuned/distilled small model with a cost-latency frontier has been reported on FinTagging.
