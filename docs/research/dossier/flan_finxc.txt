### task_summary
Extreme financial numeral labelling (XFNL): given a sentence from a 10-K and a target numeral, assign the US-GAAP XBRL tag (concept name only; NOT value/period/unit extraction). Text only, sentence level, no tables (the Limitations section explicitly says tables/paragraph context are not used). Generative reformulation: FLAN-T5 is instruction-tuned to generate the XBRL tag *documentation* text for the numeral; an unsupervised Tag Matcher (Sentence-T5-XXL embeddings + cosine similarity) maps the generated text to the closest official tag documentation. Variants: T5-Base (220M) and T5-Large (780M) fine-tuned; FLAN-T5-Large (780M) full instruction tuning, with Prefix Tuning (0.13% params), with LoRA (rank 2, alpha 32, target q,v; 0.59M trainable = 0.08%). Baselines: FiNER (bert-base / sec-base), Label Semantics, GalaXC, AttentionXML pipeline, ChatGPT gpt-3.5-turbo 5-shot on 500 samples. [VERIFIED from ACL PDF text and lora_xbrl_tuning.py]

### data
Used (not released) datasets: FNXL (Sharma et al., Findings of ACL 2023): 10-K documents for 2,339 companies; 79,088 sentences, 142,922 annotated numerals, 2,794 distinct tags, heavy tail; test set contains 67 tags absent from train/val. FiNER (Loukas et al. 2022): 139 most frequent tags (>=1000 occurrences). The FLAN-FinXC repo publishes no new dataset; README links Google Drive copies of FNXL and FiNER (no license stated). Upstream FNXL: GitHub soummyaah/FNXL (no license field) -> HF soummyaah-space/FNXL (train 1.34M / val 158k / test 219k rows, no license in cardData, 37 downloads/month). FiNER-139 on HF nlpaueb/finer-139: CC-BY-SA-4.0, train 900,384 / val 112,494 / test 108,378 sentences, EDGAR 2016-2020. No FLAN-FinXC model weights on Hugging Face (HF model search for "FinXC" returns empty). [all VERIFIED]

### reports_latency_or_throughput
partial: a single unexplained figure "inference time: 2 minutes/sample" repeated verbatim for all three FLAN-T5-Large variants (Sec. 7), with no batch size, no definition of what a "sample" is, no tokens/s, no throughput; it is not analyzed, plotted, or compared against baselines (Table 8 compares training time only). The released lora_xbrl_tuning.py evaluates with teacher-forced argmax over logits (model(**batch) then torch.argmax(outputs.logits)) rather than generate(), so the provenance of that inference figure is unclear. No latency for the Sentence-T5-XXL tag matcher. [VERIFIED]

### small_models_evaluated
T5-Base (220M), T5-Large (780M), FLAN-T5-Large (780M; full FT, Prefix Tuning, LoRA r=2) -- all sub-1B encoder-decoders. Tag matcher uses frozen Sentence-T5-XXL. No decoder-only 1-3B models, no quantized variants, no vLLM-style serving. Discrepancy: the released script sets model_name_or_path = "google/flan-t5-xl" and output dir "lora-flan-t5-xl", but its embedded print shows "all params: 738651136" (= FLAN-T5-Large) and the paper reports only Large; treat XL as unreported. ### relevance_to_idea
Strongly supports the narrow claim about this paper: FLAN-FinXC reports accuracy (Macro-F1/Hits@1), training time per epoch, and one opaque "2 minutes/sample" line, but no serving cost, no $/query, no throughput, no quantization, no accuracy-vs-cost frontier, and no latency comparison against API models (its only API baseline, gpt-3.5-turbo 5-shot, is accuracy-only). CITE it as the prior SOTA sub-1B generative approach on FNXL and FiNER (FLAN-T5-Large+LoRA 66.23 vs AttentionXML 47.54 Macro-F1). REUSE its "generate the tag documentation, then embed-match" trick (a cheap way for a small model to handle 2,794-17,388 labels) and its FNXL/FiNER splits. AVOID quoting its "2 min/sample" as a latency baseline without re-measuring. CAVEATS to the broader novelty claim found while verifying: (1) FinLoRA (Wang et al., arXiv 2505.19819, 26 May 2025; abstract: "report computational cost in terms of time and GPU memory during fine-tuning and inference stages") evaluates LoRA/QLoRA/DoRA/rsLoRA on Llama 3.1 8B on FiNER-139 and FNXL and reports fine-tuning dollars ("56.4 to 63.6 GPU hours. At an estimated rate of $0.26 per GPU hour, this translates to a cost of roughly $14.66 to $16.54" vs Gemini 2.0 FL $162.02, GPT-4o-mini $312.00) plus Figure 3 "Average inference time of LoRA fine-tuned Llama 3.1 8B and LoRA fine-tuned Gemini 2.0 FL across tasks" in seconds including FiNER and FNXL -- but 8B not 1-3B, no per-query serving $, no throughput, no quantized serving, not FinTagging. (2) FinTagging (arXiv 2505.20650) zero-shot-evaluates Qwen3-0.6B/1.7B and Llama-3.2-3B but states only aggregate "Total cost is approximately 500 GPU-hours and $1,500 in API usage"; no per-model latency/cost. (3) XBRLTagRec (arXiv 2603.25263) and Noise-Robust FNE tagging (arXiv 2605.24910), the two 2026 citers, have zero hits for latency/throughput/$. Defensible claim: no prior work fine-tunes 1-3B models for XBRL tagging and reports a quantized/vLLM serving-cost-and-latency frontier against frontier APIs on FinTagging; the phrase "nobody ... on FNXL/FiNER with cost or latency" must be narrowed because FinLoRA already reports training $ and inference seconds on FNXL/FiNER for an 8B model.
