### task_summary
Two-stage XBRL tagging benchmark over SEC 10-K narrative text AND tables (10-K only; "10-Q" appears 0 times in v5 text). FinNI (Financial Numeric Identification): input is a sentence or a whole table; output is a JSON list of (value, type) pairs where type is one of 5 XBRL data types (monetaryItemType, percentItemType, sharesItemType, perShareItemType, integerItemType). Metric: pair-level Precision/Recall/F1 — verbatim: "(e_i,l_i)=(e'_j,l'_j) if and only if both the entity span e and its assigned type l exactly match" (VERIFIED v5 PDF). FinCL (Financial Concept Linking): map each (entity, type, context) to one of 17,688 US-GAAP concepts, formulated as retrieval + LLM reranking (ElasticSearch index, OpenAI text-embedding-3-small embeddings, top-h candidates, LLM reranks). Metric: accuracy (exact match of predicted vs gold concept). Overall benchmark score: macro and micro P/R/F1 over BIO-concept labels (macro averages per concept unweighted; micro aggregates token-level TP/FP/FN) so LLM pipelines can be compared with BERT-style token classifiers (VERIFIED). TABLE INPUT FORMAT: raw HTML with structural tags — "For tables, we retain structural tags (<table>, <tr>, <td>, <th>) but discard tables without numerical facts" (VERIFIED v5); the prompt asks to "extract all such numerical entities from the provided text or serialized <table></table>"; the ground-truth JSON rows confirm contexts are literal "<table><tr><td>…" strings (VERIFIED by downloading benchmark_ground_truth_pipeline.json). For FinCL context construction (SAC strategy): "if the entity appears in a table, we linearize the entire row into a Markdown-style key-value format to serve as the context" (VERIFIED v5 appendix). IMPORTANT for the project: the output triple is (value, type, concept) only — there is NO period/date, NO unit/currency, NO scale/decimals, NO dimensional context; grep of the 6,599-record ground-truth JSON for keys cik/accession/ticker/company/fiscal/filing/period/unit/context = 0 hits each (VERIFIED). EXPERT VERIFICATION (v5 only): automated iXBRL-derived annotation of all 261,457 entities ("Validating all 261,457 entities is infeasible"), then a greedy minimal-cover "strategic audit set" of 928 sentence + 1,021 table instances (capped per company, covering every observed concept) "reviewed by two junior analysts and one senior adjudicator"; pilot calibration then independent review; "annotators achieved 96% raw agreement and Cohen's κ = 0.81" (VERIFIED v5 PDF). v1 described no human audit (VERIFIED grep: no annotator/kappa/agreement hits).

### relevance_to_idea
FinTagging is a legitimate public target and the novelty claim largely holds WITH RESPECT TO FINTAGGING: (1) every version reports accuracy only; the sole efficiency statement is the aggregate "approximately 500 GPU-hours and $1,500 in API usage" — no latency, throughput, quantization or per-model cost, so a cost/latency/accuracy frontier on FinTagging is genuinely unreported; (2) no LLM was fine-tuned — 1–3B models are only run zero-shot and score ~0.01 macro-F1, so a fine-tuned 1–3B model has a low bar on headline numbers but a very high bar on FinCL (DeepSeek-V3 reaches only 0.19 accuracy over 17,688 concepts); (3) released HF data is EVAL-ONLY (single "test" split in all 8 repos); the authors' PTM training set (10 extra 10-Ks, 1,116 sentences + 953 tables, GitHub only) is tiny, so the project must build its own training split from EDGAR iXBRL (their Algorithm 1 is a rule-based iXBRL parser) and must avoid leakage with the 142 benchmark filings — hard because v5 does NOT publish the 142 CIKs/accession numbers (only v1's 30 CIKs are listed); (4) FinTagging output is (value, type, concept) only — no period/unit/context fields — so the project's "period, unit" outputs cannot be scored on FinTagging without extending the gold data; (5) licensing is murky: 7 of 8 HF repos have no license (only FinTagging_Original is MIT) and GitHub has no LICENSE — fine for benchmarking, check before redistributing derived training data; (6) v2 datasets (28,787 / 261,457) differ from v1 (6,599 / 52,572): state the version, prefer the *-v2 repos which match paper v3–v5; (7) the official pipeline (LM-Eval-Harness/FinBen, vLLM backend) uses OpenAI text-embedding-3-small + ElasticSearch for FinCL retrieval, so a faithful reproduction has an external-API dependency for FinCL. CAVEATS to the broader claim ("nobody has benchmarked small/distilled models on FinTagging/FNXL/FiNER with cost or latency"): FinLoRA (arXiv 2505.19819, VERIFIED HTML) fine-tunes Llama-3.1-8B with LoRA/QLoRA (4/8/16-bit) on FiNER-139 and FNXL and reports fine-tuning cost ("At an estimated rate of $0.26 per GPU hour, this translates to a cost of roughly $14.66 to $16.54"; 56.4–63.6 GPU-hours on 4×A5000) plus "Figure 3 … Average inference time of LoRA fine-tuned Llama 3.1 8B and LoRA fine-tuned Gemini 2.0 FL across tasks" — i.e. inference latency for an 8B model on FiNER/FNXL-style tasks IS reported, though no serving $/doc, no throughput, no sub-8B models, nothing on FinTagging. XBRLTagRec (arXiv 2603.25263, IJCNN 2026, VERIFIED) fine-tunes FLAN-T5-Large on FNXL with no latency/cost numbers (only notes re-ranking "increases computational and API costs"). Recommended wording: "no prior work reports a serving-cost/latency/accuracy frontier for sub-8B fine-tuned or quantized models on FinTagging; FinLoRA reports training cost and inference time for an 8B LoRA model on FiNER/FNXL but not throughput, serving dollars, or sub-8B models." Cite FinTagging v5, FinLoRA, FiNER-139 (ACL 2022), FNXL (Findings ACL 2023), XBRLTagRec; reuse FinNI-eval-v2 / FinCL-eval-v2 and the FinBen vLLM harness; do not claim an HF train split exists.
