### notes
Bottom line for the project write-up: FinLoRA's Figure 3 is a wall-clock 'seconds per prompt' measurement from its own eval harness (HF transformers + bitsandbytes 8-bit LoRA adapter, un-merged PEFT, per-task max_new_tokens 10-100, no truncation, sequential or small-batch generate on A5000-class GPUs, versus sequential Vertex AI calls to a fine-tuned Gemini 2.0 Flash Lite). It is not a throughput/serving benchmark: no vLLM, no batching study, no tokens/s, no cost-per-query, no p50/p95, no table of numbers, no hardware statement specific to inference. The derived values (Llama local FiNER 1.57 s, FNXL 2.24 s, XBRL Analysis 4.58 s; Gemini 0.31/0.33/1.40 s) can be cited as 'read from Fig. 3 vector data' with the caveat that the authors never publish them. For an honest contrast, the project should (a) report the same per-prompt wall-clock metric at batch size 1 on HF transformers+bnb-8bit as a replication baseline, then (b) show vLLM/quantized serving as separate columns, and (c) note that FiNER/FNXL prompts in FinLoRA bundle 4 tagging questions per prompt and carry a long tag-option list (1.8k/7.1k avg length), which differs from FinTagging's per-document setup, so latency per fact is not directly comparable. Corrections to the user's premise: timing calls exist (in test/test_dataset.py, not inference.py); the local path does batch when batch_size>1; max_new_tokens=60 is only a default overridden per task.
