### task_summary
VERIFIED. VeriFin is a VERIFIER of LLM-generated numerical answers to financial questions over 10-K filings - not an XBRL tagger or fact extractor. Input: a question plus a candidate numeric claim produced by some answer-generator LLM; output: Verified / Violated / Abstain with traceable evidence, plus Z3 unsat cores used for guided repair. Pipeline (sections 3.2-3.6): Evidence Retriever -> Verification Planner (LLM parser that specifies metric, period, unit, operand roles, formula) -> Provenance Verifier grounds operands in filed XBRL facts and authorizes the formula from non-generative sources in a strict hierarchy (explicit operations in the question, the filing's calculation linkbase, a curated metric registry, disclosure text) -> Claim Verifier encodes quantifier-free real-arithmetic constraints and checks with Z3; tolerance is half a unit in the last place reported by the filing. XBRL facts are the ground-truth data source (structured, from EDGAR), so the paper is XBRL-adjacent but consumes already-tagged XBRL facts rather than producing tags from text/tables. Zero mentions of FinTagging, FNXL, FiNER, "tagging", "extraction", fine-tuning, distillation or quantization in the body (programmatic grep of the downloaded HTML).

### data
VERIFIED. (1) XBRLFiling: new 600-question evaluation benchmark; "We collect 86 10-K submissions from EDGAR" across 28 U.S. companies (incl. Apple, Microsoft, Amazon, Nvidia, Exxon Mobil) for fiscal years 2021-2026; built "in reverse" from each filing's XBRL calculation linkbase (subtotal p = sum w_i c_i recorded as ground truth, then a templated question e.g. "What were Apple's FY2025 total operating expenses, in USD millions?"); 15 subtotal metrics across income statement, balance sheet, cash-flow statement. No train/dev/test split - evaluation-only. Released as JSONL in repo at data/multicompany_provable/data/provable_calcrequired.jsonl (some artifacts call it "XBRLBench"); full fact-binding reruns additionally need a pinned XBRL/companyfacts archive NOT included. License: README table says "Authors' annotation license pending"; "A software license and a license for the authors' XBRLFiling questions and annotations must be selected before public redistribution." No Hugging Face dataset found. (2) FinanceBench numeric subset: 67 questions (Islam et al., 2023), CC BY-NC 4.0, exact subset shipped in repo. Repo also ships 14 VeriFin runs, 8 baseline results, 5,202 .smt2 traces, prompts (docs/PROMPTS.md). pith.science reviewer note (third-party, fetched): gold labels and VeriFin's formula authority both derive from the same calculation linkbase, i.e. a circularity caveat.

### models_and_results
VERIFIED. Candidate-claim generators (six): GPT-5.5 and Claude Haiku 4.5 (closed, via APIs); Qwen3-30B, Llama-3.1-8B, Qwen2.5-7B (open-weight; "We served the open-weight claim models with vLLM, calling them through its OpenAI-compatible endpoint; weights were downloaded from HuggingFace"); Fin-o1-8B (domain model; repo notes checkpoint identity not pinned). Verifier/planner backbone and all baseline backbones: Claude Haiku 4.5. "All calls use temperature 0 and a 2048-token response limit." Baselines: Direct LLM, LLM Judge, Judge+Formula, Program-of-Thought (PoT). Headline (Table 2, Haiku-4.5 candidate pool): XBRLFiling n=600 -> 455 true accepts, 0 false accepts, 92.2% accuracy, 98.8% coverage; "VeriFin rejects all 92 incorrect candidates ... returning a decision on 593 of 600"; baselines accept 6 (PoT) to 92 incorrect claims. FinanceBench n=67 -> 28 TA, 0 FA, 83.3% acc, 80.6% coverage; baselines accept 4-21 incorrect. Robustness (per generator, XBRLFiling): Qwen2.5-7B TA 35 / FA 0 / FR 73 / Abs 10 / acc 87.6 / cov 98.3; Llama-3.1-8B TA 74 / FA 0 / FR 50 / Abs 16 / acc 91.4 / cov 97.3; Qwen3-30B TA 245 / FA 0 / FR 69 / Abs 0 / acc 88.5 / cov 100. Zero false accepts across all six generators. Repair (Table 3): pass@1 verifier-guided repair raises recovery 6.5->46.3% (Qwen3-30B), 26.1->57.0% (Fin-o1-8B), 23.1->40.5% (Haiku); pass@3 reaches 69.9% (Fin-o1-8B, XBRLFiling). Repo caveat: "No auditable FinanceBench GPT-5.5 result artifact is present".

### relevance_to_idea
Does NOT refute the novelty claim, but requires precise framing. (1) Different task: VeriFin verifies numeric QA answers using already-filed XBRL facts; it does not do XBRL tagging / fact extraction from 10-K text or tables and never touches FinTagging, FNXL or FiNER. (2) Cost: it reports no dollar/serving cost and no training cost, consistent with the claim. (3) Latency: the project must NOT say VeriFin reports no latency - it reports a single coarse figure (3-9 s avg, 12k-17k tokens, 4-6 LLM calls per question, Z3 5 ms median) for its own pipeline only; phrase the claim as "reports accuracy but not a serving cost/latency frontier and no small-model cost comparison". (4) It does use vLLM-served open 7-30B models via an OpenAI-compatible endpoint, so "open models + vLLM in XBRL-adjacent evaluation" exists in prior work, though not fine-tuned, not quantized, not 1-3B, and not costed. (5) Cite it as adjacent work on XBRL-grounded numerical reliability and as motivation (LLMs confuse period/unit/line item - exactly the fields the project extracts). (6) Possible reuse: XBRLFiling's 600 calculation-linkbase-derived questions (concept/period/unit-specific) could serve as a downstream consistency check for extracted facts, but its license is "pending" and the software license is unselected, so do not redistribute; FinanceBench-67 is CC BY-NC 4.0. (7) Avoid confusing it with the unrelated github.com/223456png/verifin.
