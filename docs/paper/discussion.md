# Discussion

The final checkpoint’s higher micro-F1 reflects a shift toward precision, not a gain in both precision and recall. Relative to the 20,000-instance checkpoint, deduplicated precision rose from 80.43% to 87.58%, while recall fell from 97.46% to 95.73%. The final checkpoint produced 1,159 fewer unmatched predictions but left 198 more reference pairs unmatched. It therefore performed better under micro-F1, while the 20,000-instance checkpoint retained an advantage when missing a reference pair mattered more than making an extra prediction. The [Results](./results.md) report the full comparison.

As described in [Methods](./methods.md), the unit of error is a distinct normalized value–datatype pair within a context, not a filing, a table cell, or a fully specified accounting fact. A wrong type can count as both an extra predicted pair and a missing reference pair. Repeated occurrences of the same pair within a context count once, and a match does not establish that the model identified the correct concept, period, or unit. Because micro-F1 pools pair counts, contexts with more pairs can carry more weight.

## Limitations and next tests

The checkpoints came from one training run. The 20,000-instance checkpoint was taken during epoch one; the final checkpoint followed two epochs over the full filtered training set. The comparison therefore mixes exposure to new examples with repeat exposure and more optimizer steps. The paired 95% interval of +3.25 to +7.09 F1 points is for **final versus 10,000**, not final versus 20,000. It quantifies uncertainty from resampling the 17 development companies for these fitted checkpoints; it does not capture variation across training seeds or establish that the gain will transfer to other filings.

The development labels were generated from inline XBRL tags, and the manual audit was not completed. An unmatched pair is therefore a disagreement with the automatic reference, not necessarily a verified extraction error. The study includes no audited external comparison and does not establish performance on the public FinNI test set or against external models.

The most direct follow-up is to decode the saved end-of-epoch-one adapter on the same development IDs with the same settings. Comparing it with the 20,000-instance snapshot would show what changed over the remainder of the first pass; comparing it with the final adapter would show what changed during a second pass with no new training instances. To test whether distinct-example coverage matters at a fixed update budget, repeat training across seeds and compare the full corpus with a fixed subset repeated for the same number of optimizer steps. A separate external comparison should use identical held-out filings for all models and include the planned manual label audit.
